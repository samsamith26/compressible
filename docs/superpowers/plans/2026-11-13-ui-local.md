# UI Implementation Plan (Phase 1, branch `ui-local`)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the UI for the isentropic, normal shock and oblique shock calculators on the existing `@/physics` API, with the four visualizations from the spec.

**Architecture:** `src/lib` (pure helpers) → `src/hooks` (generic React state) → `src/features/<calc>` (a pure `model.ts` that maps UI state to physics calls and chart geometry, a `use<Calc>` hook, and small components) → `src/App.tsx` shell. Every non-trivial computation is a pure function tested in Vitest; components stay thin.

**Tech Stack:** Vite 8, React 19, TypeScript 7 strict, Tailwind v4 (`@tailwindcss/vite`), shadcn/ui (CLI-installed primitives), d3-scale + d3-shape, @fontsource B612 + Atkinson Hyperlegible Next, Vitest + Testing Library + jsdom, Playwright for verification.

**Spec:** `docs/superpowers/specs/2026-11-12-compressible-flow-design.md`. Standards: `CLAUDE.md`. Status: `NOTES.md`.

## Visual direction: "Colour schlieren"

Chosen with the frontend-design skill. Subject: a compressible-aerodynamics calculator for aerospace students (VT AOE 3114) and engineers. Its job: give a trustworthy number fast, and show what the flow looks like.

The idea comes from the wind tunnel's own imaging method. Colour schlieren photography shows a shock as a sharp line with cyan and magenta fringes, seen through a round test-section window.

- **The one bold element: a porthole.** Each calculator gets a circular, always-dark "test-section window" showing the flow, redrawn on every input:
  - **isentropic:** a converging-diverging nozzle, with the current station marked;
  - **normal shock:** a duct crossed by a normal shock;
  - **oblique shock:** a wedge with the oblique shock, or a detached bow shock.

  Regions are shaded by density. Shocks are drawn as a bright line with cyan/magenta fringes. Everything else on the page stays quiet.
- **Colour means station.** Station 1 (upstream) is cyan and station 2 (downstream) is magenta, the two colour-schlieren filter hues. The pair is used for table columns, chart marks and porthole regions, and nowhere else. All palettes were validated with the dataviz script (light surface `#EEF1F3`, dark `#11171D`).

  | Token | Light | Dark |
  |---|---|---|
  | `--bg` (test-section glass) | `#EEF1F3` | `#11171D` |
  | `--ink` | `#14212B` | `#E6EBEF` |
  | `--ink-2` (secondary) | `#4A5866` | `#9AA8B5` |
  | `--rule` | `#D3DAE0` | `#26313B` |
  | `--s1` station 1 | `#0A7FC2` | `#2F95D4` |
  | `--s2` station 2 | `#C2367A` | `#E2609C` |
  | `--c-p` / `--c-rho` / `--c-t` (isentropic curves) | `#5B4BD6` / `#1A8A6E` / `#B0600A` | `#8E80F2` / `#2C9F72` / `#C47E22` |
  | `--error` | `#B3261E` | `#FF8A80` |
  | `--detached` (status, with icon and label) | `#8A5A00` | `#E3B04B` |

  The porthole is always dark (`#070B10` glass) in both themes.
- **Type.**
  - B612, the typeface Airbus commissioned for cockpit displays, for headings and every number.
  - Atkinson Hyperlegible Next for UI text.
  - Both were drawn to keep 0/O and 1/l/I distinct, which matters for numbers people copy into homework.
  - Scale, ratio 1.25: 13 / 14 / 16 / 20 / 25 / 31 px. Sentence case everywhere; no all-caps labels; no mono.
- **Layout.** Left-aligned, max width 1200 px.
  - Header: wordmark, calculator switcher, theme toggle.
  - A problem line states the inputs as a sentence ("Air with γ = [1.4]. Known: [M ▾] = [2]"), like the first line of a textbook problem.
  - Then the porthole (left) beside the station table (right) from `lg` up, stacked below that.
  - Charts run full width underneath.

  ```
  Compressible   Isentropic  Normal shock  Oblique shock              ◐
  γ = [1.4]   M₁ = [2]   Known [turn angle, weak ▾] = [10] °
  ┌────────────┐  Quantity      Upstream   Weak      Strong
  │  porthole  │  M             2.0000     1.6405    0.5523
  │  (wedge)   │  p₂/p₁         —          1.7066    4.3874 …
  └────────────┘
  [ θ-β-M chart (wide) ]              [ across-the-shock chart ]
  footer: inspired by the VT calculator
  ```
- **Tables over cards.** No shadowed cards. Sections are separated by space and one hairline. The oblique table shows the weak and strong solutions side by side and emphasises the selected one. The VT calculator makes you pick one first.
- **Motion.** Porthole geometry and chart markers transition for 150 ms on typed changes and track the pointer exactly while dragging. Off under `prefers-reduced-motion`. No entrance animations.

## Global Constraints

- Import physics only from `@/physics`. No physics changes unless a real bug is found; report it if so.
- No `any`, no `as` assertions (oxlint). Small components; logic in `model.ts`, hooks or `src/lib`.
- Inputs update live, with no Calculate button. Invalid input shows the `Result` message inline, and the results keep the last valid values, dimmed.
- URL query mirrors state: `?calc=isentropic|normal|oblique&g=<γ>&k=<input kind>&v=<value>`, plus `&m1=<M1>` for oblique.
- Charts are custom SVG with d3-scale/d3-shape:
  - one y-axis per chart;
  - a legend plus direct labels when there are 2 or more series;
  - a crosshair or tooltip on hover and focus;
  - text in ink tokens, never series colours.
- Responsive down to 375 px with no horizontal scroll. Visible focus rings. Keyboard operable, including the draggable points (role `slider`, arrows ±0.1, Shift ±1).
- Footer: "Inspired by the Virginia Tech Compressible Aerodynamics Calculator", linking to https://devenport.aoe.vt.edu/aoe3114/calc.html.
- `npm run lint`, `npm run typecheck`, `npm test` and `npm run build` pass after every task. Commit per task.

## Review Focus

1. **Half-typed numbers** ("", "-", "1.", "2e", "1e-"). The field keeps the draft, shows no error until the text is a number, and results keep the last valid value. Test: `parseNumber` and the `useNumberField` tests.
2. **Switching the input kind.** The value field is re-seeded with the current solution's value for the new kind, so switching never produces an instant error. Test: `seedValue` in each model.
3. **Dragging past θmax or into another regime** (θ-β-M drag beyond the curve; isentropic drag below M = 1 with a supersonic-only kind such as Mach angle). The point clamps to the valid domain and never writes an invalid value. Tests: `dragToInput` (oblique) and `machToInput` (isentropic).
4. **A shared or reloaded URL with garbage params** (`?g=abc&k=nope`). Falls back to defaults per param, without crashing. Test: `readCalcState`.
5. **Extreme results** (A/A* = 1e30, p/p0 = 1e-40, M = 1e6). The readout formats them as 1.234×10³⁰ and charts clamp their markers to the plot area. Tests: `formatValue`, and the chart-scale clamp tests.

### Task 2: Number parsing, formatting and URL state

**Files:** `src/lib/parseNumber.ts`, `src/lib/format.ts`, `src/lib/urlState.ts`, `src/hooks/useNumberField.ts`, `src/hooks/useUrlState.ts`
**Tests:** `src/lib/__tests__/{parseNumber,format,urlState}.test.ts`, `src/hooks/__tests__/useNumberField.test.tsx`

**Interfaces:**
- `parseNumber(text: string): number | null`. Trims and accepts a decimal comma. Returns null for "", "-", "1.", "2e", "1e-", "abc", "Infinity" and NaN.
- `formatValue(x: number, sig = 5): string`.
  - Fixed notation for 1e-4 ≤ |x| < 1e6.
  - Otherwise `m×10ⁿ` with superscript digits and a real minus sign.
  - `formatValue(0.127805) === '0.12781'`, `formatValue(4.5) === '4.5000'`, `formatValue(1.2e30) === '1.2000×10³⁰'`, `formatValue(-3e-7) === '−3.0000×10⁻⁷'`.
- `type CalcId = 'isentropic' | 'normal' | 'oblique'`.
- `interface CalcState { calc: CalcId; gamma: string; kind: string; value: string; m1: string }`.
- `readCalcState(search: string, defaults: CalcState): CalcState`.
  - Per-param fallback; an unknown `calc` falls back to the default.
  - Text is kept as typed. Kind validity is checked by each feature against its own kinds.
- `writeCalcState(s: CalcState): string` (query string, stable key order).
- `useUrlState(defaults): [CalcState, (patch: Partial<CalcState>) => void]` (history.replaceState).
- `useNumberField(text: string, setText: (t: string) => void): { text; value: number | null; onChange; onKeyDown }`. ArrowUp/ArrowDown step by 0.1 of the last significant digit's place; Shift ×10.

- [ ] Write the tests, including all the Review Focus 1 strings and the garbage URL from Review Focus 4. Watch them fail, implement, verify, commit `feat(ui): number parsing, formatting and URL state`.

### Task 4: Isentropic calculator

**Files:** `src/features/isentropic/{model.ts,useIsentropic.ts,IsentropicCalculator.tsx,RatioCharts.tsx,NozzleView.tsx}`
**Tests:** `src/features/isentropic/__tests__/model.test.ts`, `__tests__/IsentropicCalculator.test.tsx`

**Interfaces (model.ts):**
- `ISENTROPIC_KINDS: readonly { kind: IsentropicInputKind; label: string; unit?: '°' }[]`, in VT order.
- `isIsentropicKind(s: string): s is IsentropicInputKind`.
- `solve(gammaText, kind, valueText): { result: Result<IsentropicState> | null; field: 'gamma' | 'value' | null }`. Null means the text isn't a number yet.
- `seedValue(kind, state: IsentropicState): string`: the state's value for that kind, at 6 significant figures. The two area kinds use `aAStar`.
- `machToInput(kind, mach, gamma): { kind; value: string } | null`. Used by chart drags. Returns null when the kind can't represent that M (Mach angle or ν with M < 1). For area, picks `areaSub` or `areaSup` from M.
- `ratioCurves(gamma, machMax = 5): { mach: number; pP0: number; rhoRho0: number; tT0: number; aAStar: number }[]`. 200 points, log-spaced, from M = 0.05.
- `nozzleGeometry(state, gamma): { wall: [number, number][]; stationX: number; shadeAt(x: number): number }`. A fixed converging-diverging contour, with the station at the x where A/A* matches on the correct side of the throat.

- [ ] Tests:
  - `solve('1.4','mach','2')` gives pP0 ≈ 0.127805. `solve('1.4','mach','2.')` returns null. `solve('1','mach','2')` gives `field: 'gamma'`.
  - `seedValue('areaSup', s(2))` = '1.68750'.
  - `machToInput('machAngleDeg', 0.5, 1.4)` is null. `machToInput('areaSub', 2, 1.4)` gives kind `areaSup`.
  - `ratioCurves` is monotone and sonic at M = 1.
  - The station is left of the throat for M < 1 and right of it for M > 1.
  - Component: typing "3" into the value updates the p/p0 cell to 0.027224; typing "abc" shows the error message and dims the table.
- [ ] Implement:
  - **Problem line:** γ, a Known select, the value.
  - **Porthole:** the nozzle.
  - **Readout:** stagnation, sonic and angle groups.
  - **Charts:** small multiples. "Stagnation ratios" (p/p₀, ρ/ρ₀, T/T₀ against M, linear 0–1, legend plus end labels) and "Area ratio" (A/A* against M, log y). Both have a marker at the current M that is draggable (writes through `machToInput`, preserving the user's input kind), and a crosshair tooltip that lists all series at the hovered M.
- [ ] Verify. Commit `feat(ui): isentropic calculator with nozzle view and ratio charts`.

### Task 6: Oblique shock calculator

**Files:** `src/features/oblique-shock/{model.ts,useOblique.ts,ObliqueCalculator.tsx,ThetaBetaChart.tsx,WedgeView.tsx}`
**Tests:** `src/features/oblique-shock/__tests__/model.test.ts`, `__tests__/ObliqueCalculator.test.tsx`

**Interfaces (model.ts):**
- `OBLIQUE_KINDS`, `isObliqueKind`, `seedValue`.
- `solve(gammaText, m1Text, kind, valueText)` returns `{ both: ObliqueFromTheta | null; selected: 'weak' | 'strong'; result: Result<ObliqueSolution> | null; field }`.
  - `both` comes from `obliqueFromTheta(m1, θ of the solution, γ)`, so the table can show weak and strong together.
  - For a β or M1n input, `selected` is weak when β ≤ β_max.
- `thetaBetaCurves(gamma, machs = [1.2, 1.5, 2, 3, 5, 10]): { m1; points: [betaDeg, thetaDeg][] }[]`. Also `currentCurve(m1, gamma)` and `thetaMaxLocus(gamma)`.
- `dragToInput(kind, m1, betaDeg, gamma): { kind; value: string }`.
  - β is clamped to [μ, 90].
  - For θ kinds, the kind becomes `thetaWeak` if β ≤ β_max, otherwise `thetaStrong`, with value θ(β).
  - For `beta` the value is β; for `m1n` it is M1·sin β.
- `wedgeGeometry(thetaDeg, betaDeg | null): { wedge: [number, number][]; shock: { x1; y1; x2; y2 } | null; bow: string | null }`. `bow` is an SVG path for the detached case: a curved stand-off shock ahead of the wedge.

- [ ] Tests:
  - `solve('1.4','2','thetaWeak','10')` gives a selected β ≈ 39.31, with both.strong.betaDeg ≈ 83.70.
  - `solve(...,'thetaWeak','30')` gives `result.value.kind === 'detached'`.
  - `dragToInput('thetaWeak', 2, 80, 1.4).kind === 'thetaStrong'`.
  - `dragToInput('beta', 2, 10, 1.4).value` = '30.0000' (clamped to μ).
  - `wedgeGeometry(10, 39.31).shock` is non-null; `wedgeGeometry(30, null).bow` is non-null.
  - Component: switching kind re-seeds the value; the detached state shows the status note "Shock detached: θ exceeds θmax = 22.97° for M₁ = 2", with an icon.
- [ ] Implement:
  - **Problem line:** γ, M₁, Known, value.
  - **Porthole:** the wedge, an attached shock, or the detached bow.
  - **Table:** Upstream / Weak / Strong, with the selected solution emphasised.
  - **θ-β-M chart:** muted reference curves with M labels, the θmax locus (dashed), and the current M curve in `--s1`. The draggable operating point is a 24 px hit target, role `slider` with aria-valuetext "β 39.3°, θ 10.0°", and a hover readout.
  - **JumpChart** for the selected solution.
- [ ] Verify. Commit `feat(ui): oblique shock calculator with wedge view and draggable θ-β-M chart`.
