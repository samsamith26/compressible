# UI Implementation Plan (Phase 1)

Written 2026-11-12. Builds on `docs/superpowers/specs/2026-11-12-compressible-flow-design.md` and the finished
physics module. The visual direction below was chosen by Claude without the frontend-design skill (not available
in the cloud session); it is open to change, see `NOTES.md`.

## Visual direction: "wind-tunnel instrument"

The app should feel like a precise lab instrument, not a SaaS dashboard: graph-paper chart grounds, hairline rules,
numbers set in a monospace with tabular figures, and two signal colours that mean the same thing everywhere.

- **Typography.** IBM Plex Sans for UI text, IBM Plex Mono for every number, ratio and axis tick. Plex was drawn for
  engineering contexts and its mono has unambiguous 0/O and 1/l. Quantities use real notation (p/p₀, ρ₂/ρ₁, θ, β, γ)
  rendered with `<sub>` instead of ASCII.
- **Colour, with meaning.** *State 1 / upstream* is a cool blue, *state 2 / downstream* a warm amber. The same pair
  colours inputs vs. results, curves before vs. after a shock, and the wedge diagram's two flow regions. Errors use
  a desaturated red; detachment uses amber with a dashed outline because it is a valid result, not an error.
  - Light: paper `#f5f3ee`, ink `#17191d`, blue `#1f5fbf`, amber `#b4540a`, grid `#e3dfd5`.
  - Dark: graphite `#0e1013`, ink `#e7e5df`, blue `#6fa8ff`, amber `#ffad5c`, grid `#1f232a`.
  - All text pairs meet WCAG AA (checked in `src/lib/__tests__/contrast.test.ts`).
- **Layout.** A slim header with the wordmark, the calculator tabs and the theme toggle. Each calculator has an input
  rail (input kind, value, γ; for oblique also M₁) and a results area: a dense key/value readout, then the
  visualizations. Two columns from `lg`, one column below. The readout reflows from 3 columns to 2 to 1.
- **Charts.** Custom SVG with `d3-scale`/`d3-shape`. A faint graph-paper grid, mono ticks, direct labels at curve ends
  instead of legends, and one emphasised curve for the current state. The operating point is a ringed dot with
  crosshair leaders to both axes.
- **Motion.** Markers and shock lines move with 160 ms CSS transform transitions when a value is typed, and with no
  transition while dragging, so drags track the pointer exactly. `prefers-reduced-motion` turns transitions off.
  Changed readout values flash once in the signal colour.

## Tasks

1. **Setup.** Tailwind v4 via `@tailwindcss/vite`; shadcn-style primitives written by hand in `src/components/ui`
   (the shadcn registry host is blocked in the cloud session), using `radix-ui`, `class-variance-authority`, `clsx`,
   `tailwind-merge`. `d3-scale`, `d3-shape`, Plex fonts via `@fontsource`. Testing Library + jsdom for hook and
   component tests. Replace the Vite starter files.
2. **Shared utilities** (`src/lib`), test-first: number parsing (`parseNumber`), significant-figure formatting
   (`formatValue`), URL query helpers, contrast checker.
3. **Shared hooks**: `useTheme` (system default, persisted override), `useQueryState` (URL sync with `replaceState`),
   `useNumberField` (text draft + parsed value, so a half-typed "1." doesn't reset the field).
4. **App shell**: header, tabs (URL `?calc=`), theme toggle, footer credit to the VT calculator.
5. **Calculators**, each as `src/features/<name>/` with a `use<Name>Solver` hook (pure state → `Result`), an input
   panel and a readout:
   - isentropic, normal shock, oblique shock. Invalid input shows the `Result` message inline, and the readout keeps
     the last valid values dimmed.
6. **Visualizations**:
   - isentropic ratio plot vs M (log y), draggable marker that sets M;
   - shock jump chart (before/after on a log scale) shared by normal and oblique;
   - wedge diagram with the shock at β, deflected streamlines, and a bow shock when detached;
   - θ-β-M chart with a family of M curves, the θmax locus, and a draggable, keyboard-operable operating point.
7. **URL state**: every calculator's inputs round-trip through the query string.
8. **Verification**: `npm run verify:ui` (Playwright) at 1280px and 375px, light and dark: no horizontal scroll,
   live updates, keyboard tab order, θ-β-M drag, detached case, URL round-trip. Screenshots go to
   `verification/` (gitignored).
9. Code review at the end; fix findings.
